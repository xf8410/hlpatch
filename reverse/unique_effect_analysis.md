## 一、三层效果体系

支援卡有**三层独立的效果**：

### 1.1 effect_table（面板加成）
- 来源: `support_card_effect_table`
- 生效时机: **游戏开始时直接加到面板**
- 不需要羁绊，不是固有
- type 9-13 = InitialSpeedUp ~ InitialWizUp（初始属性）
- type 14 = InitialEvaluationUp（初始羁绊）
- type 1-8 = 训练时加成（友情/干劲/副属性/训练）
- type 17-19 = Hint等级/Hint率/得意率

**示例**: 福星来る SSR (30286) effect_table 有 type 9 (InitialSpeedUp) init=5 → 开局 Speed +5

### 1.2 unique_effect type_0 < 100（标准固有效果）
- 来源: `support_card_unique_effect.type_0`
- type_0 = 效果类型（同 effect_table 的 type 映射）
- type_1 = 第二效果类型
- value_0 / value_1 = 效果值
- 生效时机: **bond 达到阈值后**

**示例**: 福星来る SR (20016) unique_effect: type_0=1(友情) val_0=10, type_1=14(初始羁绊) val_1=15

### 1.3 unique_effect type_0 = 101（bond 阈值标记）
- type_0=101, value_0 = 60/80/100
- **不是效果**，是触发条件标记
- 174 张卡使用此标记
- 普通卡: 80 或 100
- 友人卡: 60
- 团体卡: 80 或 100

### 1.4 unique_effect type_0 = 102-122（特殊条件固有）
- **每张卡专属的特殊触发条件**
- 不在 metadata 的枚举里，是引擎硬编码
- idle_mode_sub_rate 非 0 = 闲置时也有副效果

## 三、固有 vs 初期加成 区别

| 特性 | 初期加成 (effect_table type 9-13) | 固有效果 (unique_effect) |
|------|:--------------------------------:|:-----------------------:|
| 来源 | support_card_effect_table | support_card_unique_effect |
| 生效时机 | 游戏开始时 | bond 达到阈值后 |
| 需要 bond | ❌ | ✅ |
| 需要彩圈 | ❌ | ❌ (逛街也生效) |
| 加到面板 | ✅ 直接加属性 | ❌ 训练时乘算/加算 |
| 是固有吗 | ❌ 不是 | ✅ 是 |

**你说的"初期游戏开始时候面板直接加到属性里面"** = effect_table type 9-13 (InitialSpeedUp ~ InitialWizUp)。

这不是固有——固有是 bond 达标后在训练时额外触发的效果。初期加成是开局就有的。

## 四、特殊条件固有 (type_0=102-122) 的触发机制

这些不在 metadata 枚举里，是**引擎硬编码的卡片专属条件**。每张卡的触发条件不同：

- **type 120 (Orfevre)**: 可能是"连续训练同一属性N次后触发"或"比赛胜利后触发"
- **type 103**: 6张卡，val=4-5，可能是"训练N次后触发"
- **type 116**: 10张卡（最多），val=1-3，可能是"达到特定剧本进度时触发"
- **type 118-122**: 友人卡专用，可能与友人卡事件进度相关

**确认方法**: 需要反汇编 libil2cpp.so 中处理 unique_effect 的函数，或查看游戏内固有说明文本。
