## 一、libil2cpp.so — 游戏主逻辑 (209MB)

### 1.1 基本信息

- **格式**: ELF 64-bit LSB shared object, ARM aarch64
- **最小 API**: Android 22 (Android 5.1)
- **NDK**: r23b
- **符号表**: stripped (但 IL2CPP API 通过导出表暴露)
- **依赖**: liblog.so, libm.so, libdl.so, libc.so

### 1.2 段结构

| 段 | 虚拟地址 | 内容 |
|----|---------|------|
| .rodata | 0x01e05050 | 只读数据(字符串/常量表) |
| .text | 0x03b9ff4c | 代码段(主逻辑) |
| .data.rel.ro | 0x099c3280 | 只读重定位数据 |
| .data | 0x0a031900 | 可变数据 |

### 1.3 IL2CPP API 导出

共 **241 个** `il2cpp_*` 导出函数，是 IL2CPP 运行时给 Hachimi 等注入框架的接口：

**核心 API 分类:**

| 分类 | 关键函数 | 用途 |
|------|---------|------|
| 域/程序集 | il2cpp_get_assembly_image, il2cpp_domain_get | 获取 Gallop/Cute 等程序集 |
| 类操作 | il2cpp_class_from_name, il2cpp_class_get_methods | 按名查找类 |
| 字段读写 | il2cpp_field_get_value, il2cpp_field_set_value | 读写 WorkSingleModeData 等实例字段 |
| 方法调用 | il2cpp_runtime_invoke | 调用 get_WinSaddleArray 等方法 |
| 字符串 | il2cpp_string_new, il2cpp_string_chars | C# String 互转 |
| 内存 | il2cpp_object_new | 创建 C# 对象 |
| 自省 | il2cpp_class_get_fields, il2cpp_class_get_methods | 遍历类结构 |

### 1.4 反汇编覆盖

- **总函数数**: 177,385 个
- **反汇编大小**: 926MB (95 个 ASM 分块文件)
- **索引大小**: 143MB (functions/call_graph/float_ops/immediates/string_refs)
- **覆盖范围**: .text 段全部

### 1.5 关键命名空间分布

| 命名空间 | 类数 | 说明 |

## 二、global-metadata.dat — IL2CPP 元数据 (44MB)

### 2.1 基本信息

- **Magic**: `0xAF1BB1FA` (IL2CPP metadata magic)
- **Version**: 31 (IL2CPP 2022.x+)
- **格式**: 二进制序列化的 C# 类型系统索引

### 2.2 结构

global-metadata.dat 是 **C# 类型定义的索引表**。libil2cpp.so 里的代码通过这个文件知道：
- 哪个类叫什么名字
- 每个类有哪些字段(名字/类型/偏移)
- 每个方法的名字/参数/返回值
- 字符串字面量
- 特性(Attribute)标注

### 2.3 统计数据

| 项目 | 数量 |
|------|------|
| 类型定义(TypeDefinition) | 40,632 |
| 字段(Field) | 191,400 |
| 字符串字面量(StringLiteral) | 388,752 (3.5MB) |
| 方法(MethodInfo) | ~160,000+ |

### 2.4 作用

**没有这个文件，libil2cpp.so 就是不可读的二进制**——所有类名/字段名/方法名都在 metadata 里。IL2CPP 编译时把 C# 的类型信息从代码中剥离到单独的 metadata 文件，代码里只保留索引数字。

Hachimi/Il2CppDumper 等工具通过解析 metadata + libil2cpp.so 的方法表，可以还原出完整的类名→地址映射，这就是我们能调用 `get_WinSaddleArray` 的前提。

### 2.5 反汇编中的对应

- `reverse/il2cpp_all_classes_by_category.json` — 40,632 个类的完整分类
- `reverse/il2cpp_key_classes_methods.txt` — 关键类的方法地址列表
- `artifacts/metadata_types_full.txt` — 272,664 行的类型/字段完整 dump

## 三、libnative.so — Cygames 自研网络/数据库层 (2.6MB)

### 3.1 基本信息

- **格式**: ELF 64-bit ARM64
- **符号表**: NOT stripped (函数名可见)
- **依赖**: liblog/libm/libdl/libc

### 3.2 三大功能模块

#### 3.2.1 SQLite (数据库)

导出完整的 SQLite API:

| 函数 | 用途 |
|------|------|
| sqlite3_open_v2 / sqlite3_key / sqlite3_key_v2 | 打开/加密数据库 |
| sqlite3_prepare_v2 / sqlite3_step / sqlite3_finalize | 执行SQL |
| sqlite3_bind_* | 参数绑定 |
| sqlite3_column_* | 读取结果 |
| sqlite3_rekey / sqlite3_rekey_v2 | 更改加密密钥 |
| sqlite3mc_config / sqlite3mc_codec_data | SQLCipher 多密钥配置 |

**用途**: master.mdb 就是加密 SQLite 数据库，通过 libnative.so 的 sqlite3_key 解密后读写。游戏运行时下载数据也通过这个层。

#### 3.2.2 Tempest (HTTP/2 网络引擎)

Cygames 自研的 HTTP/2 客户端:

| 函数 | 用途 |
|------|------|
| tempest_create / tempest_destroy | 创建/销毁 HTTP 会话 |
| tempest_config_create / tempest_config_set | 配置请求参数 |
| tempest_add_header / tempest_clear_headers | 设置 HTTP 头 |
| tempest_register_request_raw | 发送请求 |
| tempest_query_progress_raw | 查询进度 |
| tempest_requests_create / tempest_requests_resize | 请求池管理 |
| tempest_global_logger_create_file / memory | 日志记录 |
| tempest_pause / tempest_restart / tempest_wakeup | 生命周期控制 |
| tempest_is_terminated | 状态检查 |
| tempest_get_elapsed_transfer_bytes | 传输统计 |

**内部依赖**:
- **libcurl** — HTTP 传输引擎(strings 里有完整的 curl cookie/HSTS/alt-svc 管理)
- **mbedTLS** — TLS/SSL 加密(strings 里有 RSA/ECC/AES/SHA256/HMAC 证书验证)
- **nghttp2** — HTTP/2 协议(帧打包/头部压缩)
- **LZ4** — 响应体压缩解压

**这就是游戏的网络层** — 所有服务器通信(训练结果上传/排行榜/继承选择)都走 Tempest → libcurl → mbedTLS → 服务器。我们的 `/api/sniff` Hook 点(CompressRequest/Post/DecompressResponse)就是在 Tempest 的调用链上截获的。

#### 3.2.3 加密/压缩

| 组件 | 用途 |
|------|------|
| SQLCipher (sqlite3mc) | 数据库加密(SEE 多密钥) |
| mbedTLS | TLS 通信加密 + 证书验证 |
| LZ4 | 数据压缩(请求/响应) |
| Brotli/gzip/deflate | HTTP 内容编码 |

### 3.3 反作弊相关

libnative.so **不包含**反作弊代码。strings 里没有 root 检测/Frida 检测/Xposed 检测/Magisk 检测相关字符串。

反作弊在别处:
- **Google Play Integrity** — Java 层(classes.dex)调用 Google API
- **_Cyan.dll** — 未在 APK 中找到(可能动态下载或服务器端)

## 四、libunity.so — Unity 引擎 (19MB)

### 4.1 基本信息

- **格式**: ELF 64-bit ARM64, stripped
- **版本**: Unity 2022.x (基于 IL2CPP version 31)
- **导出**: 仅 JNI_OnLoad + UnitySend* 等少数函数

### 4.2 作用

标准 Unity 引擎运行时:
- 渲染管线(OpenGL ES / Vulkan)
- 资源管理(AssetBundle)
- 场景管理
- 物理(PhysX)
- 音频(FMOD → CRIWare 桥接)
- 动画(Animator/Spine)

**不包含游戏逻辑** — 所有游戏 C# 代码编译到 libil2cpp.so 里了。libunity.so 只提供引擎基础设施。

### 4.3 与游戏的关系

```
libmain.so (bootstrap)
  → 加载 libunity.so (Unity 引擎)
    → 初始化 IL2CPP 运行时
      → 加载 libil2cpp.so (游戏逻辑)
        → 读取 global-metadata.dat (类型索引)
          → 加载 master.mdb (游戏数据, 通过 libnative.so)
```

## 七、反汇编数据索引

### 7.1 artifacts/disasm/ 目录

| 文件 | 大小 | 内容 |
|------|------|------|
| chunk_000.asm ~ chunk_094.asm | 926MB | libil2cpp.so .text 段完整反汇编(95块) |
| index.json | 143MB | 函数/调用图/浮点/立即数/字符串引用索引 |

### 7.2 index.json 结构

```json
{
  "functions": [file_addr, size, il2cpp_addr],  // 177,385 个函数
  "call_graph": {...},                          // 调用关系
  "float_ops": [...],                           // 浮点常量操作
  "immediates": [...],                          // 立即数
  "string_refs": [...],                         // 字符串引用
  "chunks": [{idx, start_vaddr, end_vaddr, file, functions, calls, float_ops}]
}
```

### 7.3 使用方法

1. 在 `reverse/il2cpp_key_classes_methods.txt` 找到目标方法的 il2cpp 地址
2. 在 index.json 的 functions 列表里匹配 il2cpp_addr (第三列)
3. 得到 file_addr 和 chunk_file
4. 在对应 chunk_XXX.asm 中 grep file_addr

## 八、安全分析总结

### 8.1 客户端有什么

| 数据 | 位置 | 可读 |
|------|------|------|
| 游戏逻辑(训练/继承/比赛) | libil2cpp.so .text | ✅ 反汇编 |
| 类型/字段/方法名 | global-metadata.dat | ✅ 解析 |
| 游戏数据(卡片/技能/因子) | master.mdb | ✅ SQLite |
| 网络层(Tempest/curl/TLS) | libnative.so | ✅ 符号可见 |
| 布料物理 | libcyspringandroid.so | ✅ |
| IL2CPP API(241个) | libil2cpp.so 导出表 | ✅ |

### 8.2 客户端没有什么

| 数据 | 在哪 | 能否获取 |
|------|------|---------|
| 继承发动率(70/80/90%) | 服务器端 | ❌ 只能统计 |
| 白因子获得率(20%) | 服务器端 | ❌ 只能统计 |
| 遗传子因子保底(6★40%/12★100%) | 服务器端 | ❌ 只能统计 |
| G1 因子获取概率 | 服务器端 | ❌ 只能统计 |
| 反作弊(_Cyan.dll?) | 未知/动态加载 | ❓ |

### 8.3 拦包可行性

libnative.so 的 Tempest 网络层是明文→加密的边界:
- **CompressRequest 之前**: 明文请求 body(MessagePack 格式)
- **Post 调用时**: URL + Headers 明文
- **DecompressResponse 之后**: 明文响应 body(MessagePack 格式)

三个 Hook 点已实现(`/api/sniff`)，但 MessagePack 解码尚未实现——这是获取服务器概率数据的唯一途径(如果服务器在响应里返回了计算结果)。
