概述
本报告基于 hlpatch 仓库的 IL2CPP 全量方法转储（dump_all_methods_ALL.json，19MB）和育成辅助插件源码（lib.rs，675KB），对赛马娘育成系统的内部机制进行系统性逆向工程分析。分析覆盖基础数据、羁绊系统、特殊支援卡逻辑、拉面杯剧本、比赛相关和马娘成长六大类共 35 个子项，每个子项均标注了类名、方法名、关键字段偏移和逻辑描述。
由于 Cygames 加密了 IL2CPP metadata，静态 il2cppdumper 无法直接 dump，hlpatch 使用 Zygisk-Il2CppDumper 绕过加密并配合运行时反射端点获取字段偏移。本报告中的字段偏移均来自 lib.rs 中实测验证的值。

2.1 羁绊槽增加逻辑（Bond Gain Mechanism）
羁绊（Bond/Kizuna/絆）通过 _evaluationList 管理。_evaluationList 是 List<Evaluation>，位于 WorkSingleModeCharaData 的 offset 0x3F8。
Evaluation 结构（lib.rs 第 4572-4624 行）：
Evaluation + 0x10 = partner_id（ObscuredInt）
Evaluation + 0x24 = current_bond（ObscuredInt，范围 0-100）
List 结构：
List<T> + 0x10 = _items（数组指针）
List<T> + 0x18 = _size（Int32）
T[] + 0x20 = 第一个元素
羁绊增加：训练时通过 TrainingPartnerArray 确定参与训练的伙伴，训练结束后对应伙伴的羁绊值增加。增加值受支援卡效果（桃效果：絆獲得UP）和剧本效果影响。

十、结论与建议
核心发现
数据访问路径清晰：WorkDataManager → WorkSingleModeData → WorkSingleModeCharaData 是育成数据读取的核心路径，所有属性和状态均可通过此路径获取。
CommandId 映射非对称：根性=103、力量=105（而非直觉的相反），这是实测确认的关键差异，编写工具时必须使用此映射。
羁绊系统通过 Evaluation 结构管理：每个伙伴的羁绊值存储在 _evaluationList 中，partner_id 关联到 support_card_id 或特殊 NPC ID，bond 值范围 0-100。
彩圈判定 = bond≥80 + 类型匹配：支援卡闪彩的核心条件是羁绊值 ≥ 80 且 support_card_type 匹配当前训练 CommandId。
拉面杯剧本数据模型完整：通过 ObscuredSingleModeRamenDataSet 及其关联的 20+ 个子类完整覆盖了地区选择、Feeling 系统、试食会、检查点、Uraf 效果等核心机制。
ObscuredInt 加密：大部分关键字段（属性、羁绊、CommandId 等）使用 ObscuredInt 加密（20 字节/key+hidden），必须通过运行时 getter 方法或 key⊕hidden 解密读取。
后续逆向建议
制作完整 ID 映射表：从 masterdb 数据库提取 chara_data、card_data、support_card_data 三张表的完整映射。
分析 RNG 系统：通过 _fixedTurnCharaSeed (offset 408) 的反汇编分析确定训练伙伴出现概率。
补充拉面杯道具系统：进一步搜索 Sozai、Ingredient、Recipe 等关键词，或通过运行时内存扫描定位食材计数。
ARM64 汇编分析：对 ExecTraining 等关键方法进行 ARM64 反汇编，确定训练增益计算的精确公式。
